- **Réservations payées existantes** : inchangées (décision initiale).
- **Retenue d'annulation** : passe de 2 % → 3 % pour les **nouvelles**
  annulations client seulement. Les remboursements déjà soldés ne sont pas
  retouchés (le snapshot `policy_snapshot` fige l'ancienne règle).
- **Payout part gérant** : nouveaux payouts `cancellation_fee` créés uniquement
  pour les annulations client **postérieures** au déploiement.
- **Aucune migration destructive** (`migrationLint.test.ts` interdit
  `DELETE`/`DROP COLUMN` non réversibles dans les migrations).

## Procédure

### 1. Pré-vol (lecture seule, rien n'est modifié)
```bash
cd /opt/ilehya
./deploy/preflight.sh <domaine>
```

### 2. Sauvegarde (obligatoire avant migration)
```bash
sudo /usr/local/bin/ilehya-backup /var/backups/ilehya/avant-release-20261120
```
Vérifier que le dossier de sauvegarde contient bien le dump SQL.

### 3. Contrôle des migrations en attente (lecture seule)
```bash
docker compose -f docker-compose.prod.yml run --rm api \
  node dist/db/migrateCli.js --check
```
Doit lister `0040`…`0044` comme **en attente** et afficher
`Règles de texte : aucun problème` / `Confrontation à la base : aucun problème`.

> Si le `--check` signale un blocage, **ne pas déployer** : corriger d'abord.

### 4. Déploiement
```bash
./deploy/deploy.sh
```
Le script enchaîne : build image → migrations → redémarrage → `/api/health`.
En cas d'échec d'une migration, l'ancienne version reste en ligne.

### 5. Vérifications post-déploiement
```bash
# État des migrations : plus aucune en attente
docker compose -f docker-compose.prod.yml run --rm api \
  node dist/db/migrateCli.js --status | grep -E '^\\[ \\]'   # doit être vide

# Contrôle complet
./deploy/smoke.sh https://<domaine>
```

Points à valider dans `smoke.sh` / manuellement :
- `GET /api/health` → `{"status":"ok"}`
- Réservation de bout en bout (client → gérant confirme → paiement)
- Annulation client → remboursement 97 %, et un payout `cancellation_fee`
  apparaît pour le gérant (vérifier `SELECT kind, net_amount FROM payment_payouts
  WHERE kind='cancellation_fee' ORDER BY created_at DESC LIMIT 5;`)
- Notification gérant reçue en temps réel (badge mis à jour sans rechargement)

### 6. Contrôle SQL ciblé de la release

## Rollback

Si un problème apparaît après le déploiement :

```bash
# Restauration complète (base + code) depuis la sauvegarde étape 2
./deploy/rollback.sh /var/backups/ilehya/avant-release-20261120

# OU repli code seul (après checkout du commit précédent)
git checkout 50444bf
./deploy/rollback.sh --code-only
```

⚠️ Le rollback **base** restaure aussi les données : à utiliser uniquement si
les nouvelles migrations ont causé un dysfonctionnement. Pour un simple bug
d'interface, préférer le revert code (`git revert`) suivi d'un `deploy.sh`.
